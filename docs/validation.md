# 검증 기록

2026-11-10, macOS ARM64 / Docker Desktop desktop-linux / Engine 29.9.2. 호스트 CPython 3.14.10, 컨테이너 CPython 3.14.4(Ubuntu 패키지 3.14.4-1ubuntu0.2)를 구분한다.

- 공통 Python 3.14 Ubuntu 26.04 이미지로 linux/arm64 이미지를 빌드했다. 웹 컨테이너에 Docker socket을 마운트하지 않는다.
- 실제 운영 컨테이너 16개, 이미지 15개, 공통 기반 5개를 수집했다. Host 24GiB / Docker VM 7.75GiB를 별도로 표시한다.
- 인증 전 state API는 401, 로그인 후 실제 데이터 조회와 readiness가 성공했다.
- 격리 컨테이너로 로그인 → CSRF → 호스트 토큰 → macOS flock → Engine API의 시작/중지/재시작과 실제 상태 검증을 수행했다. 같은 UUID 재시작 요청이 중복 실행되지 않았다. 소유권 확인 후 테스트 컨테이너를 제거했다.
- 데이터 유출 방지, 잘못된 daemon/ID/대상/확인 이름/상태 거절, 읽기 전용 대상, 잠금 경합, 미확정 작업, 로그인/CSRF/Origin/Host/세션/요청 크기 등을 자동 검사한다.
- 패키지 설치 도구를 제거한 실행 이미지의 Trivy 검사에서 CRITICAL/HIGH 0개, 수정 버전이 제공된 항목 0개를 확인했다. MEDIUM 44개, LOW 4개는 원본 보고서에 남긴다. 모든 취약점이 없다고 해석하지 않는다. SBOM과 검사 원본을 따로 기록한다.
- 실제 데이터의 읽기 전용 UI 검증 서버에서 로그인과 네 메뉴, 모듈 선택, 계층 탭, 실제 마운트를 확인했다. 320px/390px 모바일에서 가로 넘침과 브라우저 오류가 없었다.
- 긴 연결 오류 응답을 별도 검증 서버에서 주입해 320px 화면의 문구 줄바꿈을 확인했다. 관제 전용 모드는 1280×900에서 여섯 서비스 카드와 포트를 세로 스크롤 없이 표시했다. 대시보드의 IPv4/IPv6 중복 포트는 묶고 전체 바인딩은 컨테이너 화면에 유지한다.
- 기존 12개 컨테이너 이름을 `<module>-<role>`로 전환했다. 기존 service DNS 별칭, 이미지 ID, 포트, 모든 마운트가 동일함을 확인했다. OnlyPlus 2개와 공통 PostgreSQL은 이름을 유지했다.

운영 설정·비밀값·측정 DB·검사 세부 보고서는 로컬 operations에만 보관한다. 실제 외부 수신자에게 검증 메일을 보내지 않았다.

남은 운영 사항: OnlyPlus worker의 기존 OOM 재시작이 관측되어 관제에 종료 이력과 누적 횟수를 표시한다. 백업/복원 자동화와 Mac 재부팅 후 호스트 supervisor 자동 시작은 미연동/미검증이다. 원격 모바일의 실서비스 연결은 별도 사설 연결 또는 인증된 HTTPS 경로가 필요하다.
