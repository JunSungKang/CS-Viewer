# CS-Viewer 구조

웹/API 컨테이너는 정적 화면과 상태·제어 API를 제공하고 로컬 호스트 에이전트에 요청을 전달한다. 주소를 열면 관제 보드와 실제 데이터가 바로 표시된다.

에이전트는 지정한 Docker daemon의 Unix socket에 연결하여 명시한 인벤토리의 컨테이너를 수집한다. `module`과 `role`은 서비스 표시를 위한 모듈·실행 역할 메타데이터이다. 등록된 모든 대상에 동일한 시작·중지·재시작 동작을 제공한다.

## 수용 기준

- 관제 보드·컨테이너·계층·마운트 네 화면을 즉시 사용할 수 있다.
- 웹/API와 에이전트 요청에 사용자·세션·자격 증명이 필요하지 않다.
- 공개 배포에서는 접속한 방문자가 인벤토리 조회와 제어를 사용할 수 있다.
- 관리 인벤토리 밖의 대상과 임의 Engine API는 제공하지 않는다.
- 실제 컨테이너 ID, 예상 상태와 확인 이름, 요청 UUID를 검증한다.
- 공유 macOS flock 안에서 daemon·대상을 재확인하고 작업 이력과 실제 결과를 기록한다.
- 수집 지연이나 실패를 최신 정상 상태로 표시하지 않으며 수집 지연 시 제어를 중단한다.
- 실제 diffID와 마운트를 표시한다. 백업·복원 자동 실행은 제공하지 않는다.

컨테이너 생성·삭제, exec, 임의 파일 읽기, 이미지 변경 API는 구현하지 않는다. 측정 SQLite와 실제 운영 설정은 workspace의 로컬 operations에 둔다.
